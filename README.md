Linux Host Intrusion Detection & Audit Log Monitoring
Overview
This project documents a Blue Team host security monitoring lab completed as part of CodePath's Intermediate Cybersecurity (CYB102) program. The lab focused on configuring and using the Linux Audit daemon (auditd) as a Host Intrusion Detection System (HIDS) to monitor file activity, generate security events, and investigate those events through Linux audit logs.
The objective was to gain hands-on experience with host-based monitoring, custom detection rules, Linux logging, and security event analysis.
Lab Objectives
During this lab, I:
- Installed and verified the Linux auditd service.
- Used Vim to create and modify files in Linux.
- Created a custom Audit rule to monitor a file for write activity.
- Configured a filter key to identify events associated with the monitoring rule.
- Generated security events by modifying the monitored file.
- Examined events recorded in /var/log/audit/audit.log.
- Used ausearch to filter audit logs and isolate relevant events.
- Analyzed event fields to determine which executable and operation generated the activity.
Audit Rule Configuration
A custom rule was configured to monitor changes to the lab file:
-w /home/codepath/unit2_lab.txt -p w -k unit2_lab_changes

The rule uses -w to watch the specified file, -p w to monitor write activity, and -k unit2_lab_changes to assign a searchable key to events generated by the rule.
After configuring the rule, the Audit service was restarted so the new monitoring configuration would take effect.
Generating and Investigating Events
The monitored file was modified using Vim, causing Linux Audit to record the activity.
The full Audit log was available at:
/var/log/audit/audit.log

Because system audit logs can contain a large number of events, I used ausearch with the custom filter key to isolate the relevant activity:
sudo ausearch -ts today -k unit2_lab_changes

The resulting events were analyzed using fields such as exe, op, and key. This made it possible to distinguish between the event generated when the Audit rule was created and the event generated when Vim modified the monitored file.

Key Takeaways
This lab provided hands-on experience with the basic workflow behind host-based security monitoring:
Define suspicious or security-relevant activity → configure a detection rule → generate telemetry → filter the resulting logs → analyze the event.
The exercise demonstrated how Linux auditing can provide visibility into activity occurring on a host and how custom monitoring rules and searchable keys can help analysts efficiently identify relevant events within larger system logs.
